# Nibble

A barebone knowledge agent built on [opencode](https://opencode.ai) — a
self-RAG loop over a local Obsidian-style markdown vault: retrieve when needed
(`retrieval-hook` Brain-First gate → `rag-search`), write durable knowledge on
request (`rag-brain`), and drain the conversation backlog into notes through the
cursor-backed `drain` mission (via the `drain_run` tool).

**Status:** pre-1.0, under construction. M1–M4, M8, M9 migrated (self-RAG,
vault guards, profile, web, audit, OS agents); M5–M7 (mail/telegram/idea) +
autonomy harness phases = roadmap.

## Quick start

```bash
git clone https://github.com/Vusumzi123/Nibble-agent.git && cd Nibble-agent
./scripts/setup.sh            # install deps, connect a model, generate your local layer
./scripts/run.sh              # start Ollama (if needed) + opencode; stops Ollama on exit
```

`setup.sh` is idempotent — it skips anything already done (files, packages, model choice).

`run.sh` is the recommended entry point: it starts the Ollama embedding server on
demand, waits for it, launches `opencode`, and stops Ollama again when opencode
exits — **only if the script started it** (a pre-existing server is left alone).
Run plain `opencode` instead if you don't want Ollama (the MCP then falls back to
local transformer embeddings).

The dashboard backend (config API + web UI) is tied to the opencode process:
`dashboard-hook` starts it as a child on launch and stops it on exit; an
already-running backend (another opencode instance or a manual start) is left
alone. Reset it with `./scripts/dashboard-ctl.sh restart` (`stop`, `status`,
`logs` also work). Set `DASHBOARD_AUTOSTART=0` to disable the autostart.

## Requirements

- [opencode](https://opencode.ai) with at least one model connected.
- `git` + `node` — the RAG MCP runs from a pinned fork that `setup.sh` clones
  over **https** into `.opencode/mcp/markdown-vault/` at `MCP_SHA` and installs
  with `npm ci` (the fork's `prepare` hook compiles `dist/`). `opencode.json`
  spawns `node .opencode/mcp/markdown-vault/dist/index.js` relative to the
  project root — no `npx` at launch, so startup is sub-second and immune to
  npm cache-lock stalls, and no SSH key is needed. The whole directory is
  gitignored/regenerated; the pin is `MCP_SHA` at the top of the
  `markdown-vault MCP` block in `scripts/setup.sh` — bump it and re-run
  `./scripts/setup.sh`.
- [Ollama](https://ollama.com) with the `qwen3-embedding:0.6b` model pulled —
  required for the embedding path; `run.sh` starts the server and fails with a
  `ollama pull …` hint if the model is missing. The cross-encoder reranker
  (`ms-marco-MiniLM-L-6-v2`) downloads itself from Hugging Face on first use.
- Linux/macOS (Windows via WSL). `python3` + an API key only for the optional
  `openjev` decision provider.

## What's tracked vs. local

| Tracked (public) | Local-only (gitignored) |
| --- | --- |
| `.opencode/` — hooks, shared libs, agents, scripts | `.opencode/sysop-config.yaml` — your settings (generated from the tracked `.example`) |
| `AGENTS.md` — agent operating instructions | `Brain/` — your knowledge vault (stubs generated) |
| `SETUP.example.md`, `scripts/setup.sh` | `SETUP.md` — your machine's profile (generated) |
| | `.opencode/state/` — memory buffer, tag index, hook state |
| | `.opencode/logs/` — audit trail + every structured hook log |
| | `.opencode/mcp/` — pinned MCP fork cloned + built by `setup.sh` |

Rule of thumb: **the code is neutral, your identity lives in gitignored files.**

## The local layer (generated by setup.sh)

1. **`Brain/Agent.md` + `Brain/User.md`** — profile notes in your vault root.
   Edit them to teach the agent who it is and who it works for.
2. **`.opencode/sysop-config.yaml`** — all hooks read this live (no restart
   needed for most toggles).
3. **`SETUP.md`** — platform detection result the agent reads before touching
   your system.

## Missions

Missions live in `.opencode/missions/*.md`: the frontmatter is configuration
(id, frequency, menus, level, candidacy, lane, enabled, agent, runner,
on_decline) and the body is the child-session prompt. `runner` binds a tool to
the child (drain uses `drain_run`); it never bypasses the agent. Every mission
ends by calling `mission_result`; `on_decline: reroll` lets the orchestrator
exclude the mission and pick another one once in the same tick.

Work reaches missions through **lane queues** ([`docs/heartbeat-lanes.md`](docs/heartbeat-lanes.md)):
a tick drains a persistent work queue instead of running one thing. `lane:
primary` missions are picked by the JEV digest (one per tick); `lane: side`
missions (drain, staleness) are status-fed, ride a strict-FIFO side queue, and
run **alongside** the primary in the same tick — one side item per tick, no
expiry. Empty queues make a tick a silent no-action tick with zero LLM calls.
See [`docs/missions.md`](docs/missions.md) and
[`docs/heartbeat-mission-architecture.md`](docs/heartbeat-mission-architecture.md).

## Modes

Build is the default. **Chat** (`Tab` to switch) is a read-only conversational
mode: it stays in the injected persona, answers in short prose, and can only
look things up — brain knowledge through `rag-search`, the web through
`safe-browser`. It cannot write files or run commands; writing and OS work
stay in Build. Both modes share the same vault hooks, so conversations in Chat
are still consolidated by the drain pipe.

## The self-RAG loop

- **Retrieve:** on every user turn, `retrieval-hook` decides (fail-closed, JEV
  `noul` gate) whether the message needs a vault search; if yes it injects the
  `[brain-first]` directive and the main agent delegates to `rag-search`
  (read-only markdown-vault MCP).
- **Remember:** vault writes go through the `rag-brain` sub-agent on explicit
  request. The `drain` mission (heartbeat, cursor-backed) calls the
  `drain_run` tool, which summarizes un-consolidated turns and hands labelled
  items to `rag-brain`; the cursor advances only when the writer reports every
  item. Un-consolidated turns stay searchable through the read-only
  `memory-explorer`.
- **Memory provider:** the read plan, writer, pending count, tools, and guarded
  agents come from one active provider selected by `memory.provider` (`both`,
  `rag-brain`, `memory-explorer`, `none`). See
  `docs/knowledge-memory-modularization.md`.
- **Persona:** `profile-hook` injects `Brain/Agent.md` + `Brain/User.md` into
  the system prompt on the first turn of each session, re-injects the full
  block every `refresh_every_turns` turns (persona-fade mitigation; rebuilt
  from disk so mid-session note updates apply), and at idle decides
  (JEV `choice`) whether the turn carried durable new information worth writing
  back through a short-lived `profile-writer` child.
- **Browse:** `webfetch`/`websearch` are denied to the main agent and allowed
  only for the read-only `safe-browser` child. Every fetched page runs through
  the deterministic injection scanner (`web-scan-hook` → `lib/injection.ts`)
  and comes back fenced as untrusted data with a one-line `[web-scan: …]`
  brief; full findings go to `.opencode/logs/web-scan.log`.
- **Audit:** every `bash` command is appended (secret-redacted, deterministic)
  to `.opencode/logs/audit.log` by `audit-hook`; `telemetry-hook` records
  sub-agent delegation usage to `.opencode/logs/rag-search.log` and
  `web-usage.log`. All logs and state are project-local — gitignored, never in
  `$HOME`.
- **OS ops:** destructive and system-touching commands route through the
  `security-locks` go/no-go sub-agent (7 locks: dry-run default, explicit
  confirmation, command whitelist, graphical-only root escalation, no
  persistent sudo), with `package-manager` preparing lifecycle commands and
  `sandbox-runner` isolating arbitrary execution. Flow: `AGENTS.md` §5–§6 +
  the `os-security` skill (escalation ladder, dry-run workflow).
- **Decisions:** every gate routes through `lib/decision-gate.ts` →
  `lib/decisions.ts` — the `openjev` provider
  (`.opencode/scripts/decisions_bridge.py`, stdlib-only Python) with a
  deterministic `rules` fallback and an explicit open/closed polarity chosen
  per call site.

## Optional upgrades

Ships fully deterministic out of the box; two features are opt-in:

- **Smart retrieval gate** — the default `decisions.provider: rules` makes the
  per-turn Brain-First gate fail closed to SKIP (retrieval still fires on an
  explicit "search my notes" intent). For a model-backed gate set
  `decisions.provider: openjev` and `decisions.model: <provider>/<model>` (any
  model from `opencode models`) in `.opencode/sysop-config.yaml` — the endpoint
  and API key are resolved from opencode's own credentials, so no separate
  `base_url`/`api_key_file` is needed. Requires `python3`.
  For the typed Clef path set `decisions.backend: clef-openrouter` and
  `decisions.model: openrouter/cloudflare/clef`: OpenRouter's
  `/api/alpha/decisions` returns the same calibrated probabilities as the local
  model without occupying VRAM (requires an OpenRouter credential).
  `scripts/setup.sh` option 5 writes it; `backend: clef` keeps the local/offline
  variant.
- **Profile auto-writes** — `profile.writer_model` is empty by default, so the
  agent inherits the session model. Set it to a registered `provider/model` to
  pin the writer; a missing or failed model is a logged no-op and never blocks
  the session.

## Development

```bash
npm --prefix .opencode ci                          # test-only dependency
node --test .opencode/plugin/lib/*.test.ts .opencode/plugin/lib/drain/*.test.ts
python3 scripts/tests/test_provider_resolve.py     # decision-provider resolver
```

The runtime does not need `node_modules` — opencode supplies the plugin API when
loading hooks, so `npm ci` is only for running the test suite.
