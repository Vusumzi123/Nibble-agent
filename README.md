# ecco

A self-hosted, autonomous agentic harness built on [opencode](https://opencode.ai)
— an AI agent that manages your operating system with defense-in-depth security:
per-action autonomy levels (L0–L4), a hard irreversibility floor, dry-run-first
package operations, a full audit trail, and a RAG knowledge vault.

**Status:** pre-1.0, under active construction. See `docs/autonomy-harness-plan.md`
for the roadmap and `Boards/` for the live Kanban boards.

## Quick start

```bash
git clone <this-repo> && cd ecco
./scripts/firstboot.sh        # generates the local-only layer (see below)
opencode                      # open the project — the agent reads SETUP.md
```

`firstboot.sh` is idempotent — it only creates files that don't exist yet.

## What's tracked vs. local

| Tracked (public) | Local-only (gitignored) |
| --- | --- |
| `.opencode/` — plugins, agents, skills, scripts | `.opencode/sysop-config.yaml` — your personal settings (generated from the tracked `.example`) |
| `AGENTS.md` — agent operating instructions | `.opencode/agents/*.md` — any personal agent modes you add locally |
| `docs/`, `Boards/`, `diagrams/` — plans & boards | `Brain/` — your knowledge vault (stubs generated) |
| `SETUP.example.md`, `scripts/firstboot.sh` | `SETUP.md` — your machine's profile (generated) |
| | `.opencode/state/` — conversation buffers & indexes |

Rule of thumb: **the code is neutral, your identity lives in gitignored files.**

## The local layer (generated by firstboot)

1. **`Brain/Agent.md` + `Brain/User.md`** — profile notes injected into every
   top-level session (agent persona / user context). Edit them to teach the
   agent who it is and who it works for.
2. **`.opencode/sysop-config.yaml`** — all hooks read this live (no restart
   needed for most toggles). Replace the `you@example.com` placeholders.
3. **`SETUP.md`** — platform detection result the agent reads before touching
   your system (package manager, escalation tools, sandbox, config paths).

## Safety model (short version)

- Nothing runs unsupervised: destructive actions require explicit confirmation,
  everything defaults to dry-run, and a hard-coded deny list survives even the
  highest autonomy level.
- Every command is logged to an audit ledger with exit code and elevation status.
- Secrets live in the KDE keyring / chmod-600 files — never in the config.

Details: `AGENTS.md` (agent contract) and `docs/autonomy-harness-plan.md` (design).
